# Stage 22: Director signals and pop-out Studio

Goal: the show follows the music more closely (switch on musical phrases, zoom and bloom on kicks, clear energy tiers in the colour), and the Studio can live in its own window so the main window stays a clean full-screen visual.

Status 2026-11-13: planned. Order confirmed by Charlie: 22.1 (A), 22.2 (B), 22.3 (D), 22.4 (C), then 22.5 to 22.7 (E). Source issues: #28, #20, #19, #21, #29.

Read `README.md` in this folder first. Needs Stage 21 merged (Visuals menu selector 21.13, lazy Studio 21.8, service worker 21.10).

## Why
- Auto-cycle has Off, Timer and Beat. Beat mode switches on any strong kick, which can land mid-phrase. Tracker data for bars already exists (`barPhase`, `beatCount` in `src/audio/tempo.ts`, carried on `AudioFrame`) but nothing switches on it.
- The Global Director camera only drifts with `smoothedEnergy`. A kick pushes colour (`burstIntensity`, `getColorUniforms`) but never the camera.
- Punchy and Wild (Slice 17.5, `src/presets/reactionStyles.ts`) pulse feedback zoom and rotate on the beat but not Post bloom. Particle kick push already exists.
- Colour reacts to energy only as a smooth mix. There are no named chill, build and drop states.
- The Studio sits over the visual in the main window. There is no way to see the visual clean while editing.

## Scope decisions
- Charlie, 2026-11-13: do A, B, D, C, E in that order. Drop the "track scene centroid / spherical orbit" part of issue #20.
- Photosensitivity limits in `src/render/safety.ts` are never loosened. Current values: cap rise at most `RISE_PER_SEC` 0.3 per second (Reduced 0.2, Calm 0.15); at most `MAX_REVERSALS_PER_SEC` 3 reversals per second (Calm 2); `FlashGovernor` allows at most 1 flash per `MIN_FLASH_GAP_SEC` (1/3 s); brightness ceiling 1.0 (Reduced 0.9, Calm 0.75). New kick effects stay under these and never bypass the final safety pass in the compositor.
- The pop-out is a second window of the same app on the same origin. The main window owns audio and rendering. The pop-out owns only the Studio UI.

- **22.1** The live cycler is `src/presets/autoCycle.ts`. `src/presets/autoCycler.ts` is an older copy with the same class name; `main.ts` does not import it. Do not touch it. Add mode `'phrase'` to `CycleMode`, `phraseBars` (default 8; options 4, 8, 16) to `CycleOptions`, saved in `mv.autoCycle` with `mode`, `shuffle`, `intervalSec` (old saved data without it loads fine). Fall back to the Timer rule when `tempoConfidence` is below 0.5 or `bpm` is 0 or the frame has no `beatCount`. `next()` and `upcoming()` need the beat count; add an optional argument rather than reordering. For `upcoming()`, prepare the next preset when the current bar is the last before the boundary (`barPhase` near 1 on beats `4N-1`) or use the Timer lead rule in fallback. - **22.2** Add a kick impulse (peak offset at most 0.05 of zoom before intensity scaling, decay about 0.25 s) fired on the existing `kickHit` in `advance()`. It is added in `getCameraUniforms` after the intensity scaling (so it scales by camera intensity) and before the `minFloor` clamp. It is zero when `isCalm()`. At most one impulse per `MIN_FLASH_GAP_SEC` (1/3 s) so it cannot exceed 3 per second. It is a spatial change, not a luminance change, so the brightness cap is untouched; the unit test asserts the limits above. The director cannot see the viewer Intensity setting (Full, Reduced, Calm) which lives in `BrightnessLimiter`; this slice does not add that link. Ask Charlie if Reduced should also halve it. The Director cannot see Intensity today, so add a `setKickZoomScale(scale)` setter (1 Full, 0.5 Reduced, 0 Calm), clamped to 0..1, and call it from the per-frame block in `src/main.ts` that already passes `state.intensity` to `compositor.brightnessLimiter.setIntensity`. `src/main.ts` is therefore a Target file of 22.2. Test the three scales.
- **22.3** The styles live in `src/presets/reactionStyles.ts` (PUNCHY, WILD). Add a `kick` response on a `strongBeat` trigger targeting `post('bloom')` (range 0 to 2) to PUNCHY; WILD inherits it. Suggested amount 0.2 of the range (0.4 bloom), ease 0.3. Bloom is off at 0 so the pulse works from base 0. The reaction engine in `src/presets/reactions.ts` does not use `flashGovernor` today. Gate kick reactions that target post `bloom` through `flashGovernor.tryFlash(timeSec)` so at most 3 pulses per second show. A refused pulse is skipped, not delayed. Presets that set their own `bloomPulse` keep it; the two stack, so cap the sum (reaction plus preset) at the control maximum, which `reactions.ts` already clamps. Tests: Punchy and Wild contain the reaction; Gentle and Off do not; the flash gap holds over a fast beat train. Reaction styles default to Off, so default looks do not change.
- **22.4** Add a tier value (`chill`, `build`, `drop`) derived from a rolling energy level (slower than `smoothedEnergy`) with hysteresis: separate enter and leave thresholds plus a minimum dwell time so it does not flicker. In `getColorUniforms` the tier adjusts `intensity` and mood weighting by a blended weight (smooth over about 1.5 s), never a hard step. Stays under the existing `Math.min(1.0, ...)` intensity bound. Calm mode keeps its current behaviour (no drop boost). Reset in `reset()`. Edit `globalDirector.ts` only after 22.2 is merged.
- **22.5** New `src/studio/popoutChannel.ts`. Use `BroadcastChannel` named `mv-studio-popout` (not `mv-admin-auth`). Message envelope: `{ v: 1, from: 'main' | 'popout', origin, id, type, ... }`. Receiver drops a message when `v` is wrong, `origin` differs from `location.origin`, `type` is not in the allowlist, or the size is over a cap. Allowed types only: `hello`, `snapshot` (preset id and name list, shown preset id, shown preset JSON), `select-preset`, `edit` (preset id, target section and layer index, control name, value), `heartbeat`, `bye`. No type may carry an admin, identity, token, or write-to-server request. Reject keys `__proto__`, `constructor`, `prototype`. Module must not import Tweakpane or `studio.ts`, because `main.ts` imports it and the main bundle must stay free of Studio code. Pure logic plus a thin wrapper around `BroadcastChannel`, so tests run in node with a fake channel.
- **22.6** Needs a way to run Studio without a GPU. `Studio` takes a `PresetSession`, and the session needs a compositor-like object (the interface near `session.ts:258`). The pop-out builds a session with a no-op compositor, loads the same builtin and user presets (same-origin local storage is shared), and subscribes to snapshots for the shown preset. Add an optional `onEdit` hook to `Studio` (central point: `bindSpec` and `bindSection`) that the pop-out uses to send `edit` messages. No hook means no change in the main window. New HTML entry `popout.html` at the repo root plus `build.rollupOptions.input` in `vite.config.ts` (main `index.html` and `popout.html`). The lazy `import('./studio/studio')` chunk from Slice 21.8 must stay out of the main entry; check bundle output lists before and after. Static assets: the Worker only runs first for `/admin` and `/admin/*` (`wrangler.jsonc`); `/popout.html` is a real built file so `single-page-application` fallback does not apply and no Worker or `wrangler.jsonc` change is needed. Confirm in the built `dist/` listing. Risk: this is the largest slice. If `Studio` depends on live compositor state beyond the session interface (frame readout, link meters), stub those in the pop-out and say so in the PR.
- **22.7** New `src/studio/popoutHost.ts` (main window side): applies `edit` and `select-preset` messages through narrow session setters only, validates and clamps each value with the control's `ParamSpec`, and never calls `saveSystemPreset`, `deleteSystemPreset`, `promoteUserPreset` or any remote writer. Sends a `snapshot` on `hello` and when the shown preset changes. Heartbeat every 2 s; either side treats 6 s of silence as disconnected, and reconnects when the other window reloads or reopens. While a pop-out is connected, the in-page Studio hides and the main Studio button and key E focus the pop-out instead. Add a "Pop out" button (the Studio header or Visuals area in `index.html`) and a key (Shift+E, listed in the shortcuts dialog). Pop-ups open from a click, so `window.open` is not blocked; if it is, show a toast. Service worker (`public/sw.js`): bump `CACHE_VERSION`; navigations to `/popout.html` must not overwrite the cached `/index.html` shell (today `networkFirst` caches any navigation as the shell); `/admin` stays uncached.
- **Security.** The admin gate is not reachable from the channel: messages carry no identity, and admin state is decided per window by the server (`/admin/api/identity`, Cloudflare Access cookie), never by a message. The channel is same-origin only, but any same-origin script could already edit local storage, so it adds no new privilege; still, treat every incoming message as untrusted input (allowlist, size cap, value clamping, no server writes). Preset Studio admin actions (save to server, delete, promote) run only in the window where the admin is signed in, through that window's own gateway. The `mv-admin-auth` channel and `mv.adminAuthSignal` key are not reused or relayed. Worker responses keep `frame-ancestors 'none'` and `X-Frame-Options: DENY`; the pop-out is a window, not a frame, so no change. The Studio admin login flow inside the pop-out (popup handshake, `mv.returnToStudio`) must be tested by hand by Charlie.

## Done when
- With Phrase selected and a track with a steady tempo, the preset changes on the first beat of every 8th bar. With no tempo it behaves like Timer.
- On a kick the camera makes a short zoom-in that eases back, and it is absent in Calm. Punchy and Wild show a bloom swell on strong kicks, never more than 3 per second.
- The colour visibly moves between chill, build and drop sections without flicker.
- A pop-out Studio opens from a button or Shift+E, edits show in the main window, the main window shows no Studio while it is connected, and closing or reloading either window recovers.
- The main bundle still contains no Studio or admin code.
